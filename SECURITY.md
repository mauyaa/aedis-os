# Security and privacy

Report vulnerabilities privately to the repository owner. Never place credentials or inspection evidence in a public issue.

## Implemented controls

- OpenAI and webhook credentials remain server-only.
- Expiring signed sessions bind server-generated user, organization, display workspace, and inspection session IDs.
- An optional judge access code is server-only, timing-safe compared, and attempt-throttled.
- Binary signatures, declared/decoded formats, byte size, pixel count, dimensions, strict Zod bodies, and request/frame IDs are validated.
- Per-session best-effort throttles limit analysis, Realtime starts, reports, and incident proposals.
- Three-minute action tokens bind the user, organization, inspection session, finding, severity, exact action version, destination, expiry, and nonce.
- External delivery, when configured, uses a fixed server destination, HMAC-SHA256, timeout, and idempotency key.
- Report identity is derived from the signed session. Dates, statuses, incident formats, text bounds, and chronology are validated.
- CSP, frame ancestry, MIME sniffing, referrer, and camera/microphone permission policies are set.
- Continuous video and raw audio are not uploaded or stored; evidence capture is explicit.
- `OPENAI_LIVE_ENABLED=false` prevents optional provider calls in the judge deployment.

## Honest limits

Browser-local history is not organization storage. Serverless memory makes throttles and consumed nonces best-effort across instances. The PDF checksum verifies generated bytes rather than evidence truth. The Local Spatial Engine is an inspection aid, not an electrical-safety certification.
